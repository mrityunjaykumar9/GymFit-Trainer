1 Host your privacy policy permanentlyYou

GitHub Pages hosts a single page for free, forever, with no subscription of any kind attached to it — the most standard choice for exactly this situation.

  1. Go to github.com/signup and create a free account, if you don't already have one.
  2. Click the + in the top-right corner → New repository. Name it freegymtrainer-privacy, make sure Public is selected (Private won't work — Google's reviewers need to reach it without logging in), and click Create repository.
  3. On the new repo's page, click Add file → Upload files. Drag in the file from your project at store-listing/privacy-policy/index.html. Before committing, rename it in GitHub's upload box from index.html to exactly index.html at the repo root (it already has that name — just don't let it nest inside a folder).
  4. Scroll down, click Commit changes (the default "main branch" option is fine).
  5. Go to the repo's Settings tab → Pages (left sidebar). Under "Build and deployment", set Source: Deploy from a branch, Branch: main / (root) → Save.
  6. Wait about a minute, then refresh that Pages settings screen — it'll show your live URL: https://<your-github-username>.github.io/freegymtrainer-privacy/
Use that github.io URL everywhere from here on — Play Console's privacy policy field, your store listing, everywhere. It has no expiry and no dependency on Claude, a subscription, or anything else you'd need to keep renewing. If you ever need to change the wording, edit the file in the GitHub web UI and commit — the live page updates within a minute.
2 Create two accountsYou
  1. Google Play Console — play.google.com/console/signup. One-time $25 fee, needs your Google account, a payment method, and ID verification (can take a day or two to clear — start this early since later steps wait on it).
  2. Google AdMob — apps.admob.com. Free, same Google account works.
3 Create real AdMob ad unitsYou Then me

Right now every ad in the app — the banners and all three interstitial spots — uses Google's shared test ad IDs. They prove the wiring works, but they will never earn a rupee; you need your own ad units before this makes money.

In the AdMob console: Apps → Add app → Android → "No, not published yet" → name it "Free Gym Trainer". Then under that app:

  • Ad units → Add ad unit → Banner (e.g. "Home/Nutrition/Progress banner")
  • Ad units → Add ad unit → Interstitial (e.g. "Post-action interstitial")

Copy three values: the App ID (ca-app-pub-XXXX~YYYY), the Banner ad unit ID, and the Interstitial ad unit ID (both ca-app-pub-XXXX/ZZZZ). Send all three to Claude — it's a 4-line edit in app/build.gradle.kts's release block (the debug block stays on Google's test IDs on purpose, so testing never risks your real account).

4 Generate your signing keyYou

In Android Studio, with the project open: Build → Generate Signed App Bundle / APK → Android App Bundle → Next → Create new...

  • Save the .jks file outside the project folder (e.g. Documents/) — never inside the git repo.
  • Set a store password and key password.
  • Fill in the certificate identity fields (minimal/personal is fine — not shown publicly).
  • Finish creating it, then cancel out of the rest of the wizard for now — you'll return to it in Phase 5.
This file cannot be recovered if lost. Save the passwords in a password manager. Losing this key means you can never update your app under the same listing again.
5 Build the final signed releaseYou

Once Phase 3's ad IDs are wired in: Build → Generate Signed App Bundle / APK → Android App Bundle → Next → select your keystore, enter the passwords → choose the release build variant → Finish.

This produces app-release.aab — the exact file you upload to Play Console in Phase 7.

Free Gym Trainer is a completely free, offline fitness companion — no login, no cloud, no subscription.

🏋️ Workouts — Follow built-in programs (Push Pull Legs, Upper/Lower, Fat Loss Circuit, Beginner Full Body, Home Workout) or build your own from 60+ exercises with custom sets, reps, and rest timers. Track every session with a live rest timer and set-by-set logging.

🧘 Yoga — A dedicated flows section with guided poses, step-by-step photos, and hold-based tracking, separate from the gym experience.

🥗 Nutrition — Personalized calorie and macro targets, a full food database with vitamins & minerals for 50+ foods, veg/non-veg meal plans, and one-tap water tracking.

📊 Progress — Streaks, personal records, weight and body-measurement trends, and a consistency calendar to see your habits build over time.

🔒 Private by design — Every bit of your data stays on your device. No account, no server, no data collection beyond what's needed to show ads.

Free forever, supported by minimal ads that never interrupt an active workout.

7 Fill out Play ConsoleYou
  1. Create app → name "Free Gym Trainer" → Free → answer the standard declarations.
  2. App content (sidebar) — complete every item: Privacy policy (paste your github.io URL from Phase 1), Ads ("Yes, my app contains ads"), Data safety form (no personal data collected/shared beyond AdMob's own ad-serving disclosures), Content rating questionnaire (fitness app, no violence/gambling), Target audience (not primarily for children).
  3. Store listing — paste the descriptions above, upload the icon/screenshots/feature graphic from Phase 6.

The step that catches every first-time developer off guard: a brand-new personal Play Console account cannot publish straight to Production. Google requires a closed test first — go to Testing → Closed testing, create a track, upload the same app-release.aab, and add at least 12 testers by email (friends/family Gmail addresses are fine). Share the opt-in link Play Console gives you; each tester has to install the app and open it at least once. This track must stay active for 14 continuous days before the Production track becomes available at all. Start this the same day you finish Phase 5 — it's the long pole in the whole timeline, not something to leave for last.

Once the 14 days have passed and testers have opted in: Production → Create new release — upload app-release.aab, write release notes ("Initial release"), save, roll out. Google reviews new apps before they go live — typically a few hours to a few days on top of that.

8 After it's liveYou
  • Real ads start serving and accumulating revenue immediately once Phase 3's real IDs are live — no separate "turn on ads" step.
  • In AdMob, add a payment profile (Payments → Set up payments) with your bank details and tax information — in India this means your PAN. Payouts run monthly once your balance crosses the regional threshold (commonly $100).
  • To update later: bump versionCode/versionName in app/build.gradle.kts, rebuild via Phase 5's wizard using the same keystore, upload as a new Play Console release — no new closed test required for updates to an app already in Production.
