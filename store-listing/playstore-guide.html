1 Host your privacy policy permanentlyYou

GitHub Pages hosts one page for free, indefinitely, with nothing to renew — the standard choice for exactly this.

  1. Sign in at github.com (create a free account if you don't have one).
  2. Top-right + → New repository. Name it freegymtrainer-privacy, set it Public (Private won't work — Google's reviewers open it logged-out), click Create repository.
  3. On the repo page: Add file → Upload files. Drag in store-listing/privacy-policy/index.html from your project. Keep the name index.html and leave it at the repo root (not inside a folder).
  4. Click Commit changes (default branch is fine).
  5. Settings tab → Pages (left sidebar). Under "Build and deployment": Source: Deploy from a branch, Branch: main / (root) → Save.
  6. Wait ~1 minute, refresh the Pages screen. Your live URL appears: https://<your-username>.github.io/freegymtrainer-privacy/. Open it once to confirm it loads.
That github.io URL is the one you use everywhere — Play Console's privacy-policy field and the store listing. To change wording later, edit the file on GitHub and commit; the page updates within a minute.
2 Create your real AdMob ad unitsYou then Claude

Every ad in the app currently uses Google's shared test IDs — they prove the wiring works but never earn anything. You need your own units.

In AdMob: Apps → Add app → Android → "No, not published yet" → name it "Free Gym Trainer". Then under that app, Ad units → Add ad unit:

  • One Banner unit (name it e.g. "Home/Nutrition/Progress banner")
  • One Interstitial unit (name it e.g. "Break-point interstitial")

Then send Claude these three values:

  • App ID — ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY (has a ~)
  • Banner ad unit ID — ca-app-pub-XXXXXXXXXXXXXXXX/BBBBBBBBBB (has a /)
  • Interstitial ad unit ID — ca-app-pub-XXXXXXXXXXXXXXXX/IIIIIIIIII

It's a 4-line edit in the release block of app/build.gradle.kts. The debug block stays on Google's test IDs on purpose, so any testing you do never risks your real account.

Also, in AdMob → App settings: set Maximum ad content rating to G (matches a fitness app rated for everyone) so no unsuitable ads serve inside your app.
3 Generate your signing keyYou

Every release is signed with the same key for the life of the app. In Android Studio with the project open: Build → Generate Signed App Bundle / APK → Android App Bundle → Next → Create new…

  • Save the .jks file outside the project folder (e.g. a keystores/ folder in Documents) — never inside the repo.
  • Set a keystore password and a key password (can be the same). Alias: freegymtrainer.
  • Certificate fields: your name and country is enough — it's not shown publicly.
  • Create it, then you can cancel the rest of the wizard — you'll come back in Phase 4.

Then create keystore.properties in the project root (already git-ignored) so command-line and CI builds can sign too:

keystore.properties

storeFile=C:/Users/mrity/Documents/keystores/freegymtrainer.jks
storePassword=yourStorePassword
keyAlias=freegymtrainer
keyPassword=yourKeyPassword

This file cannot be recovered if lost. Back up the .jks in two places and put both passwords in a password manager. Lose it and you can never update this listing again. (Google's Play App Signing, which you'll accept on first upload, protects the download key — but you still must keep this upload key.)
4 Build the final signed releaseYou

After Phase 2's real ad IDs are in: Build → Generate Signed App Bundle / APK → Android App Bundle → Next → pick your keystore, enter passwords → build variant release → Finish.

Output: app/build/outputs/bundle/release/app-release.aab — the file you upload to Play Console. (Command-line equivalent, now that the wrapper is committed: gradlew bundleRelease.)

Before building, bump nothing — versionCode 1 / versionName "1.0.0" is correct for the first release. You only bump these for updates after the app is live.

6 Fill out Play ConsoleYou

In Play Console: Create app → name "Free Gym Trainer", language English, type App, Free, accept the declarations.

Then work down the left sidebar. The ones with specifics for this app:

  • App content → Privacy policy — paste your github.io URL from Phase 1.
  • App content → Ads — "Yes, my app contains ads."
  • App content → Data safety — the app's own storage is all on-device, so the only thing to declare is what the Google Mobile Ads SDK does:
    • Data collected & shared: Device or other IDs — purpose Advertising or marketing; not used for a user account; can't be deleted by the user.
    • Data is encrypted in transit: Yes.
    • Everything else (name, health info, photos, location, etc.): not collected — it never leaves the device.
  • App content → Content ratings — fill the questionnaire honestly: fitness/health app, no violence, no sex, no gambling, no user-generated content. Result is "Everyone / PEGI 3".
  • App content → Target audience — target age 13+ (do not include under-13 — that triggers Google's Families policy and extra ad-SDK requirements you don't need).
  • App content → Health apps declaration — it's a general fitness/wellness app, not a medical device, no health-data sharing. The in-app disclaimer ("general information, not medical advice") already covers this.
  • App content → Government apps / News / COVID — No to all.
  • Store settings → App category — Health & Fitness.
  • Main store listing — paste the text from Phase 5, upload icon + feature graphic + screenshots.
7 Closed test → then ProductionYou

A new personal Play Console account cannot publish straight to Production. Google requires a closed test first: at least 12 testers, opted in and keeping the app installed for 14 continuous days. This is the long pole — start it the day your .aab is ready, not last.

  1. Testing → Closed testing → Create track (the default "Alpha" track is fine).
  2. Testers tab → create an email list → add 12+ Gmail addresses (friends, family, other accounts of yours). On first upload, accept Play App Signing when prompted.
  3. Releases tab → Create release → upload app-release.aab → release name "1.0.0" → release notes "Initial release" → save & roll out.
  4. Copy the opt-in URL and send it to every tester. Each must open the link, tap "become a tester", install from Play, and open the app once. Ask them to leave it installed.
  5. Wait 14 days from when testing starts. Track the countdown on the closed-testing page.
  6. After 14 days, Play Console unlocks Production. Production → Create release → upload the same app-release.aab (or a newer build) → roll out.

Google reviews new apps before they go live — usually hours to a few days after you submit Production.

8 After it's liveYou
  • Real ads serve and accrue revenue automatically once the Production build (with Phase 2's IDs) is live — there's no "turn on ads" switch.
  • AdMob → Payments → Set up payments: add your address, then your bank account and tax info (India: PAN). AdMob also mails or shows a verification PIN once you cross ~$10 — enter it or payments stall. Payouts are monthly after you pass the threshold (₹ equivalent of ~$100).
  • Updates: bump versionCode to 2 and versionName to "1.0.1" in app/build.gradle.kts, rebuild with the same keystore, upload as a new Production release. No new closed test needed once the app is in Production.
  • Keep targetSdk current — Google raises the required API level every year around August.
